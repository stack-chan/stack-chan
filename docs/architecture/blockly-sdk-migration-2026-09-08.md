# Blockly・顔エディターのSDK移行

残件の進め方 1 に対応する。比較元は `fe550a7aa44b07ca37632643d381a8948310f4ad`、共有ブランチは `codex/firmware-sdk-redesign`。

Blockly、顔エディター、Galleryの4ブロック例を `defineApp / setup(app)`、app API 2 / host API 8へ揃えた。生成コードの独自ランタイム、Timer、raw入力の差し替え、Piu顔クラスの生成、歌のコンパイラーの埋め込みを削除した。周期処理・入力購読・待機・音声は既存AppSessionの所有と取消しを使う。

## 保持する機能と契約

- ボタンの押下・解放、頭のスワイプ・なでる操作、IMUの入力をSDK購読へ接続した。頭のジェスチャーは購読の実行中抑止より前に選別する。同じ通知内のスワイプとなでるイベントが片方を落とさない。
- 首の時間はms、角度は度へ生成する。音符選択値は元からHzであるため、その値をtoneへ渡す。`motion.hold()` は最後に指令した姿勢を保持し、物理的な現在位置の計測を約束しない。
- 歌は公開拡張 `singing(app).sing(bpm, score, {signal})` に統一した。かな・音程・長さの検証とkoe生成は共通契約に1つだけ置き、通常音声と同じ物理出力占有・取消しを使う。旧非公開の文型譜面ブロックは削除し、現在の三つ組リスト形式へ案内する。
- 図形の顔は検証済みデータとして渡す。WebとSDKが同じ形状の型・検証を使い、ホストが描画部品を所有する。選択時にデータをコピーし、失敗時は前の顔を維持し、アプリ終了時に標準の顔へ戻す。
- メニュー、LED、表情・色、吹き出しも公開SDKへ接続した。ループ上限とブロック位置のエラー報告は生成コードに残し、寿命の管理を重複させない。手続きの引数取得をインストール済みBlocklyの変数モデルAPIへ直した。

## 検証

リポジトリーのnpm wrapper、Moddable 9.5.0、ESP-IDF 6.1を使用し、成果物は `firmware/dist` に出力した。

| 対象 | 結果 |
| --- | --- |
| SDK strict・公開依存 | 成功。Blocklyの5代表プログラムと各顔付き版も実際に生成してstrict検査 |
| Node単体 | 555件成功 |
| アーキテクチャ・manifest | 77件、6 target成功 |
| XS | 全60 manifests成功。実Piu/RuntimeContextで100回の開始・終了、顔の復元、解放入力・なでる通知・購読数を確認 |
| Web | legacy試験238件、React試験、ビルド成功 |
| Chrome / WASM | Gallery 4例をビルド。生成MODの顔の描画、440Hzの再生、押下・解放、差し替え後の周期処理と待機中処理の停止を確認 |
| WASM | ビルド成功 |
| CoreS3 / Core2 SG90 / Stackchan RT | releaseビルド成功。CoreS3は6,711,248 bytes |

ブラウザー試験はWebの `npm run test:generated-sdk` で再実行できる。生成MOD・4例のarchive・顔のスクリーンショットは `firmware/dist/blockly-sdk` に置く。Nodeで単に生成文字列を比較するだけでなく、SDK呼び出し、取消し、データ検証、実際のXS実行を検査した。
