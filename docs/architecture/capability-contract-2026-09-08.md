# 能力名と起動前検査の統合

項目4のうち、公開能力の定義と実行時の判定を接続した記録。機種識別と全配布経路の能力照合は続けて扱う。

## 実装

- `contracts/capabilities.js` をSDK能力名と最小host API世代の正本にした。SDKのCapabilityIdはこの定義から導出し、Webの別名・古い型宣言・重複した世代表を撤去した。
- 全archive readerで未知・撤去済みの能力名と、能力より古い世代を名乗る宣言を拒否する。必須・任意のどちらも名前と世代を検証する。
- RuntimeContextの同じ判定を起動時とSDKから使う。構成済みの機器を確認してからアプリ本体を評価する。必要な能力がなければホスト資源を解放し、復旧画面へ能力名を表示する。任意能力はアプリ内で代替動作を選べる。
- HTTP/クラウド会話はJS moduleの存在だけで成功とせず、HTTP/HTTPS clientの実際のportも確認する。サーボがない構成は利用不可とし、能力を列挙するためにサーボを開始しない。
- Webシミュレーターのcamera・録音・再生・clips・settingsをプロファイルへ反映し、未知のtargetをportableへ読み替えない。
- 追加した日本語・中国語表示に合わせてCJK subsetを再生成。既存の固定source hashを検証する再生成スクリプトを追加し、全localeの354 codepointを収録した。

SDKの構成試験は、参照する可搬な共通契約のimportも再帰的に検査する。ホスト実装やPiuへの依存を契約ファイルの裏へ移して検査を回避できない。SDK manifestのallowJsは共通JS契約から型を導出するために必要であり、SDKのstrict/checkJs検査は維持している。

## 検証

- Node全552件、SDK strict、構成77件、6対象のmanifest検査に成功。
- XS全58 manifestに成功。実Piuのライフサイクル試験で能力の全件判定、問い合わせ中にmotionを開始しないこと、HTTP moduleがあってもclient portがなければ利用不可になることを確認。
- WebのNode試験238件、React77件、Web/WASMビルドに成功。5つの完全なSDKガイド断片をstrict型検査した。
- Chromiumの実WASMへinstallerを迂回してarchiveを渡しても、必須audio.radioがない場合はアプリ本体の評価前に拒否する。旧・未来APIの拒否、設定画面の再入と、戻った後の正常アプリの一度だけの開始も確認。
- 最新WASMで録音→再生、tone、取消し・再起動、遅い権限許可・decode、view破棄後の解放を再確認。
- 最新WASMで4つのGalleryブロックarchive、生成した顔・入力・音声、置換時の待機・周期処理取消しを確認。顔・入力教材とboard_diagnosticsも起動・操作した。
- CoreS3 / Core2 SG90 / RTのreleaseビルドは6,694,864 / 3,997,408 / 4,118,064 bytes（9.5.0+stackchan.9）。実機への書き込みは行っていない。

## 検証成果物の鮮度

直接実行したブラウザー試験の一部が、前回のWebビルドに含まれた古いWASMを参照していた。これを受け、preview起動前に `web/simulator` と `web/dist/simulator` のmc.js・mc.wasmをバイト照合するようにした。違う場合は試験を開始せず、WASMビルド後のWebビルドを要求する。

上記のChromium結果はWASM→Webの順で再ビルドし、照合を通過した成果物で再実行した結果である。接続取消し・設定保存の直前コミットに記載したブラウザー結果も、この最新成果物での回帰確認によって補完した。Node・XS・nativeの結果とブラウザー成果物の鮮度を混同しない。

## 続く境界

CLI・WebSerial・SDが読むボード識別と、機種ごとにビルドが備える機能の正本を接続する。チップ名だけでは同じESP32-S3を使う別のボードを区別できず、flash上のdescriptorだけでは現在の設定や周辺機器の実状態まで確認できない。この区別を保った検査・表示が必要である。

設定schemaの詳細検査を配布側へ接続すること、無線機能の競合制御、provider参照ライブラリーの統合、音声置換と再接続の残る境界、実機および初学者受入を継続する。製品ソースの純減も未達である。
