# ｽﾀｯｸﾁｬﾝ v2.0.0

v2.0.0では、ファームウェア、型定義、ブラウザー用MODコンパイラー、シミュレーターをModdable SDK **10.0.2**へ統一します。ホストを先に更新してから、新しいコンパイラーで作ったMODを導入してください。SDK移行による旧ホスト・旧APIとの互換性の変更を含むため、firmwareとWebツールをともにmajor更新とします。

## 更新手順と互換性

1. 必要な本体設定とMODのソースを控え、対応する機種のホストファームウェアを更新します。Webのファームウェア書き込みでは、本体設定と導入済みMODが消去されます。
2. 設定を再登録し、ホストの互換性識別子とMODの要求capabilityを確認します。`10.0.2+stackchan.2`はSDK版とhost API世代を示す識別子で、製品版の`2.0.0`とは別です。
3. 新しいブラウザーコンパイラーはXS **17.9**アーカイブを生成します。SDK 9.5ホストの対応範囲はXS 17.7–17.8のため、新しいアーカイブを書き込む前にホストを更新してください。

- SDK 10.0ホストのアーカイブ判定範囲はXS 17.7–17.9です。範囲内でも、MODが使うモジュールやhost APIが存在することまでは保証しません。旧SDKで作ったMODも、使用APIを確認して必要に応じて移植・再ビルドしてください。
- 旧`sntp`、`mdns`、classic network socketのimportを使うソースは、現在のECMA-419 provider/APIへ見直してください。TypeScriptのコンストラクターやPiu templateの型にもSDK 10の変更があります。
- CLIのMOD書き込みが認識するSDK系列は9.5.xと10.0.xです。旧8.3.x/9.0.xなどの未対応ホストは、MOD導入前に更新が必要です。
- Media Playerの共有音量`audio.volume`はhost API **2**が必要です。Galleryは対応していないホストへの導入を拒否します。
- ソースビルドにはModdable SDK **10.0.2**を使用します。ブラウザーコンパイラーの再ビルドにはEmscripten **5.0.1**も必要です。SDK 9.5、10.0.0、10.0.1への途中の移行内容は、今回の10.0.2構成へ統合しています。

## 主な変更

### SDK、通信、開発ツール

- HTTP、NTP、DNS-SDとCoreS3電源処理をSDKの現在のAPIへ移行し、HTTP keep-aliveの要求状態を分離しました。SDKの新しいネットワークモジュール配置に対応し、HTTP/MCP、WebSocket、TextEncoder/Decoderを保持しています。
- package MODのビルドで、packageの作業ディレクトリに依存せずボード定義を解決し、大文字を含むパスとpackage名に沿ったアーカイブ出力を扱うようにしました。
- Core2/CoreS3のSDK標準device providerを再利用し、Stack-chan固有のカメラバス、ポーリングタッチ、ヘッドタッチ、サーボ、電源、音声、USB配線を保持しました。Analog、SPI、PulseCount、PulseWidthなどのnative IOも引き続きホストから利用できます。
- SDK標準のFiles/FAT/SDSPIへSD MOD読出しを移行しました。遅延マウント、サイズ・アーカイブ互換性・書込み後検証を保持し、マウント失敗時にはフォーマットしません。音声保存UIやhot swap保証は追加していません。
- XSテスト・デバッグの実行をSDKのxsdbへ揃えました。

### 音声と会話

- PodcastとMP3 WebRadioを一つにまとめたMedia Player MODを追加しました。RSS・アートワーク、エピソード選択、一時停止・再開、シーク、再生終了を扱い、画面を閉じても再生を継続できます。再生元の切替と古いcallbackの干渉を防ぎます。
- 保存済み`tts.volume`を音声再生と共有します。Media Playerから高・中・低・ミュートを選べ、再接続せずに反映できます。WebRadioも保存音量に従うため、50%設定のgainは従来の0.2から0.1になります。メディアの最大gainは0.2です。
- MP3の44.1/48 kHz入力、HTTP Range、redirect、上限付きRSS・JPEG取得に対応します。HTTPSからHTTPへのredirectは拒否します。再生位置の再起動越しの保存、AAC/HLS、Radikoには対応していません。
- opt-inのCoreS3 WebRTC RealtimeConversationと、直接OpenAIへ接続するGPT-Live MOD例を追加しました。native音声、tool call、開始・停止・muteを扱い、認証情報や会話設定はMOD側で管理します。通常ホストで自動接続する機能ではありません。
- CoreS3 HTTPSの同一origin接続再利用、書込み待ち、cleanup後のDNS callback、WebRTC構成のcodecとallocatorの競合を修正しました。

### 本体、Face、操作

- M5StackChan CoreS3の内蔵ST25R3916を`device.sensor.RFID`として公開しました。RFIDはopt-inで、UID検出・除去、ポーリング、アンテナ停止、明示的なType 2 NDEF URI読書きのサンプルを用意しています。MIFARE ClassicのデータIOには対応していません。
- M5StackChan専用サーボの既定pitch範囲をメーカー推奨の5–85°へ制限しました。範囲外や正面の要求は制限内へ収め、既存の校正と明示的な軸制限は保持します。
- CoreS3の低遅延Wi-Fi leaseを追加しました。leaseがない間はmodem sleepを使い、低遅延接続の所有中は起きた状態を維持します。
- PY32のLED初期化に一度だけ200 msの待ちを入れ、初回RGB書込みのI2C失敗を修正しました。Core2とタカオ版Core2のXS stackも増やし、報告されていたPiu起動ループに対応しました。
- ジト目とDeal With ItのFace表現、再利用可能な行単位の吹き出しを追加しました。Faceの自動動作を止めていても直接の表情更新を反映し、重なった傾き・なで反応の後は元の表情へ戻します。
- 設定のアクションボタンにSDK RoundRectを使い、行とヘッダーの描画を整えました。Wi-Fiパスワードはヘッダーの確認ボタンで確定できます。起動失敗時は安全なエラー種別とRestart操作を表示します。
- 本体のSettingsを開いてから5分間だけ、対応キーへのBLE設定書込みを受け付けます。Settingsを離れると受付を閉じ、機種固定の設定は読取り専用にします。

### WebツールとMOD Gallery

- Stack-chan CATCHとJUMPを同じMini Gamesアーカイブ・Gallery packageへまとめました。
- Block Editorのダークモードのカテゴリ表示、プロジェクト改名後の古いビルド結果、起動設定を開いているシミュレーターの誤った起動timeoutを修正しました。シミュレーターは初期化や`onLaunch`の例外も起動失敗として通知し、「起動中」のまま残らないようにしました。

# Stack-chan v2.0.0

v2.0.0 aligns firmware, typings, the browser MOD compiler and simulator on **Moddable SDK 10.0.2**. Both packages receive a major version bump because older hosts and SDK APIs are no longer supported by all installation paths.

## Upgrade the host first

Save the settings and MOD sources you need, update the host, restore settings, then rebuild and install compatible MODs. Web firmware installation erases preferences and installed MODs. The descriptor `10.0.2+stackchan.2` identifies the SDK and host API generation; the product version is `2.0.0`.

The new compiler emits XS **17.9** archives. SDK 9.5 hosts accept only XS 17.7–17.8 and must be updated first. SDK 10.0 hosts accept XS 17.7–17.9 at the archive level, but the imported modules and required host capabilities must also exist. Review legacy `sntp`, `mdns`, network socket imports and TypeScript/Piu types when migrating MOD sources. CLI installation recognizes SDK 9.5.x and 10.0.x hosts; unsupported older firmware requires a host update. Media Player's shared `audio.volume` requires host API **2**.

Source builds use SDK **10.0.2**; rebuilding the browser compiler also requires Emscripten **5.0.1**. Intermediate SDK migration notes are consolidated into this final version.

## Highlights

- Updates network APIs and module locations, isolates HTTP keep-alive request state, retains HTTP/MCP, WebSocket and text encoding utilities, and fixes package MOD path and archive resolution.
- Reuses standard Core2/CoreS3 device providers while retaining board wiring and native IO. Moves SD MOD reads to standard Files/FAT/SDSPI with lazy mounting and no formatting after a mount failure.
- Adds Media Player with Podcast and MP3 WebRadio, shared saved volume, pause/resume, seeking, artwork and playback beyond the view lifetime. The default 50% WebRadio volume now gives gain 0.1 rather than 0.2; the maximum remains 0.2. Playback positions do not survive restarts; AAC/HLS and Radiko are unsupported.
- Adds opt-in CoreS3 WebRTC RealtimeConversation and a direct OpenAI GPT-Live MOD example. Fixes HTTPS reuse, request cleanup and codec/allocator integration. These features do not connect automatically in the normal host.
- Adds opt-in built-in RFID support and Type 2 NDEF examples, safe 5–85° default pitch limits, low-latency Wi-Fi leases, PY32 LED startup settling and the Core2 XS stack fix.
- Adds Jitome and Deal With It face expressions and row-based balloons; fixes overlapping reaction restoration, settings button/row drawing, Wi-Fi password confirmation and startup error presentation.
- Restricts BLE preference writes to supported keys during a five-minute Settings window and keeps platform-locked preferences read-only.
- Combines CATCH/JUMP in Mini Games and fixes dark Block Editor labels, stale builds after project renames and simulator readiness during startup settings. Explicit startup failures now settle readiness even when initialization or `onLaunch` fails before the boot timeout is armed.

## Validation boundaries

The firmware snapshot tested on X1 was **177291a62f2a31a8002f27a553ea36dff8120b2f**. Firmware source remains unchanged; the release candidate also fixes Web simulator startup-failure reporting, covered by software regression tests. See the release PR for its final candidate SHA and CI/preview.

The M5StackChan CoreS3 passed the automated 30m5s condition, 17 programmatic Drawer cycles, 61 HTTP polls, 16 large responses, HTTP/WS/PCM regressions, and camera/audio actions before and after the soak. Camera rendering and record/playback completed four times each with no observed reboot or communication failure. Protected flash-region hashes matched, and the temporary MOD was removed.

Settings UI and BLE confirmation are user-reported without itemized conditions or counts. Three true power cycles, image appearance, audibility, manual servo behavior, Web installation/Gallery/editor workflows and destructive reset steps remain unverified here. SD/LCD interactions, other hardware and external TLS/WSS/conversation interoperability also need separate checks. The full physical release gate is **not** recorded as passed.

When published, `stack-chan-firmware-v2.0.0.zip` will contain `com.m5stack`, `com.m5stack.core2`, `com.m5stack.cores3` and `m5stackchan_cores3`; RT and Takao remain source-build targets. Check the accompanying SHA-256 file after publication. The stable and develop sites remain separate, and release PRs use their Cloudflare preview.
