# ｽﾀｯｸﾁｬﾝ v2.0.1

M5StackChan CoreS3でMediaPipe BLE追従MODを開始しても`STK`が見つからない問題を修正しました。顔が表示されていても、ホストが`ble local peer transport is not supported`でMODのBLE開始に失敗することがありました。

CoreS3専用manifestで実機用Local Peer bindingを選択するよう修正しています。Settings画面のBLE接続と、低遅延Wi-Fiの電源制御は維持します。

## 更新方法

[安定版Web書込み](https://stack-chan.github.io/stack-chan/web/flash/)でM5StackChan CoreS3のホストを更新してください。MediaPipe MOD **1.2.1**はそのまま使用できます。同じパーティション構成からの更新では、設定やMODを消去する操作は不要です。

通常起動後、[顔追従ページ](https://stack-chan.github.io/stack-chan/web/mediapipe/)で`STK`を選ぶと、アプリ内探索で`stackchan-mediapipe`へ接続します。BLE開始のための追加メニュー操作やカメラ開始は不要です。BLEはSettingsやMODが必要時に開始します。

製品版とWeb書込みmanifestは**2.0.1**です。SDKは**10.0.2**、ホスト互換識別子は`10.0.2+stackchan.2`を継続します。

## 検証範囲

M5StackChan CoreS3実機で、既存MODを保持してホストだけを更新し、広告・GATT接続・アプリ探索・再接続・Settingsの設定通知・顔追従を確認しました。設定値は変更せず、保護領域のハッシュとMODの識別情報も更新前後で一致しています。

切断直後の再接続はBlueZで中断する場合がありました。接続できない場合は切断を待ち、再探索してください。再起動なしのSettingsからMODへの切替、異なるパーティション構成からの移行、ほかの機種の実機動作は今回の検証範囲に含みません。

# Stack-chan v2.0.1

Fixes MediaPipe BLE failing to advertise `STK` on M5StackChan CoreS3. The face could remain visible while the MOD logged `ble local peer transport is not supported`. The board-specific host manifest now selects the physical ESP32 Local Peer bindings. Settings BLE connectivity and the Wi-Fi power policy are retained.

Update the M5StackChan CoreS3 host through the [stable Web installer](https://stack-chan.github.io/stack-chan/web/flash/). Existing MediaPipe MOD **1.2.1** remains compatible. No settings/MOD erase is required when retaining the same partition layout.

After normal startup, select `STK` on the [MediaPipe page](https://stack-chan.github.io/stack-chan/web/mediapipe/); application discovery then reports `stackchan-mediapipe`. No extra menu action or camera startup is required for BLE. Settings and MODs open BLE when needed.

The product version and Web flash manifests are **2.0.1**. SDK **10.0.2** and host compatibility identifier `10.0.2+stackchan.2` remain unchanged.

A host-only update retaining the installed MOD was verified on M5StackChan CoreS3: advertising, GATT, application discovery, reconnects, Settings notifications and face tracking. No preference values were changed; protected flash-region hashes and MOD identity matched before and after the update. An immediate reconnect was aborted by BlueZ; waiting for disconnect and rescanning succeeded. Same-boot Settings-to-MOD transitions, other partition-layout migrations and physical operation on other boards were not tested in this release.
