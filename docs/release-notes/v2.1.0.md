# ｽﾀｯｸﾁｬﾝ v2.1.0

通常のM5Stack CoreS3とM5StackChan CoreS3のファームウェアに、WebRTC会話のネイティブバックエンドを標準搭載します。会話を使うMODを別途導入して開始する構成で、ホストの更新だけで会話やマイク送信が自動的に始まることはありません。

## 変更

- WebRTCを標準CoreS3ホストと配布ZIPに含めます。未使用時は会話用HTTPS Worker・音声タスク・I2Sを起動せず、終了時はネイティブ音声の解放を待ちます。HTTPS Workerは要求と終了通知のキューを処理し終えてから解放し、次の要求で作り直します。MODの非同期終了処理も、ホストの音声解放より先に完了させます。
- Moddable SDKを10.1.0へ更新し、TLS 1.2のサーバー認証に関するセキュリティ修正を取り込みます。修正にはホストの更新が必要で、MODだけの更新では反映されません。実験的なTLS 1.3は有効にしません。
- 任意導入のAvatar DSL Face MODを追加します。default・omega・aokkoのプリセットで表情、まばたき、視線、口、呼吸を扱い、描画とアニメーションを制限付きのネイティブバックエンドで実行します。標準の顔は変更しません。MOD用ホストの再ビルドとMODの導入が必要です。
- Webツールに[Avatar DSLエディター](./face-dsl-webtools.md)を追加します。編集・インポート・Undo、C/WASMプレビュー、DSL/AVBCのダウンロード、確認操作を伴うFace MODの転送準備に対応します。Mono eyeプリセットを追加し、実験的なWebMCPがないブラウザーでも通常の編集機能を使えます。実機転送には対応ホストの確認、利用者の確認クリック、USBポート選択が必要です。
- Avatar DSLの関数末尾が条件付きreturnの場合に、プレビューが検証エラーで停止したり、次の関数を実行したりする問題を修正します。
- Webのファームウェア書き込みは全消去を既定でOFFにします。全消去が必要な場合だけ、警告を確認して選べます。通常書き込みでも対象セクターは更新されるため、設定やMODの保持はパーティション配置・書込み範囲・データ形式の互換性がある場合に限ります。
- シミュレーターの起動失敗メッセージに英語と簡体字中国語を追加します。

## 互換性と更新時の注意

製品版とWeb書き込みmanifestは **2.1.0**、SDKは **10.1.0** です。ホストAPIは **2** のままで、既存のフラッシュパーティション配置は変更しません。非S3機種にはWebRTCバックエンドを追加しません。

WebとCLIのMODインストーラーはSDK 10.1.xホストに対するXS 17.7〜17.9のアーカイブを認識します。アーカイブ形式の互換性だけでは、MODが必要とするホストモジュールや機能の有無は保証しません。

ソースビルドでは1ターゲットにつき1構成を使います。構成変更時の自動cleanは廃止したため、必要な場合は明示的に `npm run clean` を実行するか、別のworktreeを使ってください。大きなVM・キャッシュを使うLive用性能設定は引き続き任意です。

Avatar DSLの `begin_group(x,y,w,h)` は絶対座標の半開区間を厳密にclipし、入れ子では親との共通部分を使います。以前のプレビュー版や上流のgroup hintとは異なるため、独自プログラムは描画対象をgroup内に収めてください。LCD送信用の固定バッファは8.75 KiBです。ホストへのHTTP/NVSアップロードは今回の範囲に含みません。

## 検証状況

firmwareとWebの自動試験、Avatar DSLのcompiler受け入れ・native/WASM比較・ブラウザー試験を確認しています。候補SHAごとのCIと確認結果は[リリースPR](https://github.com/stack-chan/stack-chan/pull/773)に記録しています。自動試験と実機確認は区別し、以下の未検証範囲を残して公開します。

2026-11-09〜10の候補M5StackChan CoreS3 appと既存の実機パーティションで、メンテナー本人が顔・メニュー、音、録音・再生、カメラ、サーボ、LEDを確認しました。別途適合させた会話MODで通常の音声会話が成功し、サーバー側の会話終了・provider finalized・履歴保存も確認しました。今回のcompiler修正について追加の実機試験は行っていません。

M5StackChan CoreS3では、診断overlayによる実音声の接続・停止・通常音声復帰を2回続けて確認しました。各回で実際の応答PCMを受信し、UIと同じ停止処理で資源を解放した後、通常TTSと500 msの録音・再生が成功しています。1回目の復帰後の再接続も成功しました。入力は固定合成音声、出力はミュートで、周辺音声は送信していません。

診断2回目のunderrun4件は、出力キュー不足区間が始まった回数であり、音切れ4回を意味しません。診断出力はミュートだったため、原因と聴感への影響は未特定で、継続観測とします。通常会話の成功は、全native taskのstack余裕、アンプ障害復帰、長時間運転、未実施の共通リリース実機テストの合格を意味しません。これらは未検証のままです。

元のアプリと保護領域の復元一致、元ファームウェアのreadyを確認しました。実機試験は既存パーティションへのapp-only更新で、full-bundleによる移行は未検証です。異なるパーティション構成からの移行で設定やMODの保持を保証しません。保持条件は[Web書き込み仕様](../operations/web-firmware-flash.md)を参照してください。通常M5Stack CoreS3の実機受け入れは、メンテナー判断により今回の公開前条件から外し、不具合報告が発生した場合に追跡します。通常CoreS3を実機検証済みとは表示しません。

Avatar DSLエディターの実機USB転送、パネル表示、ホストのまばたき・呼吸との同時動作、長時間運転も未検証です。自動テストの転送確認はモックであり、実機合格を意味しません。

詳細は[WebRTC受け入れ条件](../operations/cores3-webrtc-acceptance.md)と[リリース前実機テスト](../operations/release-device-test_ja.md)を参照してください。

# Stack-chan v2.1.0

Standard M5Stack CoreS3 and M5StackChan CoreS3 firmware now includes the native WebRTC conversation backend. A conversation MOD must still be installed and started explicitly; updating the host does not automatically start a conversation or transmit microphone audio.

## Changes

- Include WebRTC in standard CoreS3 hosts and release bundles. Conversation Workers, media tasks and I2S are not started while unused. Native audio closure is awaited, the HTTPS Worker is retired only after its queue drains, and optional asynchronous MOD cleanup finishes before host audio shutdown.
- Update firmware, typings, CI, the browser MOD compiler and simulator to Moddable SDK 10.1.0, including its TLS 1.2 server-authentication security fix. Update the host to receive the fix; a MOD-only update is insufficient. Experimental TLS 1.3 remains disabled.
- Add an opt-in Avatar DSL Face MOD with the pinned default, omega and aokko presets. A bounded native Piu/Poco backend handles animation, bytecode execution, geometry and rendering. The standard face remains the default. Rebuild a host with the MOD's native module and install the MOD separately.
- Add the [Avatar DSL Web editor](./face-dsl-webtools.md): edit/import/undo, bounded C/WASM preview, DSL/AVBC downloads and face-MOD transfer preparation with explicit confirmation. It includes Mono eye and works without experimental WebMCP. Device writing requires acknowledgement of a compatible native host, a trusted confirmation click and browser USB-port selection.
- Fix Avatar DSL functions ending in a conditional return being rejected during preview or falling through into the next function.
- Keep full-flash erase off by default in the Web installer, with an explicit erase-all choice and data-loss confirmation. Normal writes still erase their destination sectors. Retention requires compatible storage offsets, write ranges and data formats; it is not guaranteed merely by leaving full erase off.
- Localize simulator startup failures in English and Simplified Chinese.

## Compatibility

Product packages and Web flash manifests are **2.1.0** with SDK **10.1.0**. Host API **2** and existing partition layouts are unchanged. Non-S3 boards do not gain the native WebRTC backend. Web and CLI MOD installers accept XS 17.7–17.9 archives for SDK 10.1.x hosts; archive compatibility does not guarantee all required host modules or capabilities.

Builds assume one configuration per target. Configuration changes no longer clean automatically: run `npm run clean` explicitly or use a separate worktree. The larger Live VM/cache/timing profile remains opt-in.

Avatar DSL groups now use strict absolute half-open clipping and nested intersections, unlike earlier previews and upstream group hints. Custom programs must enclose all intended pixels. Fixed LCD pixel buffers use 8.75 KiB. Host HTTP/NVS uploads are not included.

## Validation status

Automated validation covers firmware and Web tests, Avatar DSL compiler acceptance, native/WASM parity and browser behavior. Candidate-specific CI and results are recorded in the [release PR](https://github.com/stack-chan/stack-chan/pull/773). Automated tests and hardware acceptance are distinct; this release retains the unverified scope below.

On November 9–10, 2026, the maintainer checked the candidate M5StackChan CoreS3 app on the existing device partitions: face/menu, audio, recording/playback, camera, servos and LEDs. Normal voice conversation with a separately adapted conversation MOD succeeded, and server-side conversation closure, provider finalization and history persistence were confirmed. No additional physical-device test was performed for the compiler fix.

M5StackChan CoreS3 passed two consecutive real-audio lifecycle cycles using a diagnostic overlay. Each received actual downlink PCM, invoked the UI-equivalent stop method, released resources and recovered normal TTS plus 500 ms zero-PCM recording/playback. Reconnection after the first recovery succeeded. Fixed synthesized input and muted output avoided ambient-audio transmission.

Cycle 2 recorded four underruns. This counts the start of output-queue starvation intervals, not four audible interruptions. Muted diagnostic output leaves the cause and acoustic impact undetermined; observation will continue. Successful normal conversation does not establish all-native-task stack margins, amplifier fault recovery, long-duration stability or unperformed common release checks. These remain unverified.

The original app/protected-region restoration and original firmware readiness were verified. Device trials updated only the app on existing partitions; full-bundle migration remains untested. Settings and MOD retention across different partition layouts is not guaranteed; see the [Web flashing specification](../operations/web-firmware-flash.md). Ordinary M5Stack CoreS3 hardware acceptance is deferred to issue-driven follow-up by the maintainer, not claimed PASS.

Avatar DSL editor physical USB transfer, panel rendering, concurrent host effects and device soak remain unverified. Transfer automation uses mocks, not physical devices. See the [WebRTC acceptance record](../operations/cores3-webrtc-acceptance.md) and [release device checklist](../operations/release-device-test_ja.md).
