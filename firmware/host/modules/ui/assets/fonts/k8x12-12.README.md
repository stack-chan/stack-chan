# Body font resource

`k8x12-12.fnt` and `k8x12-12.png` are generated from the existing `k8x12.ttf`, the full `k8x12-chars.txt` repertoire, printable ASCII and the three host localization catalogs. They keep the 12px font metrics and monochrome glyph rasterization used by the host. The font keeps its existing Piu name, `k8x12-12`.

The host manifests package this standard BMFont resource through Moddable's `*-alpha-monochrome` conversion. The atlas then occupies one bit per pixel. For this glyph repertoire, the BMFont table plus the one-bit atlas is smaller than the per-glyph RLE4 `.bf4`. No Japanese characters are removed to fit the 4MB M5Stack.

Moddable 9.5's generated Makefile currently passes `monochrome` to fontbm, but its TrueType `*-alpha` rule still converts the resulting atlas to Gray16. A pre-generated BMFont and the existing PNG monochrome rule avoid changing the SDK or generated Makefiles. The source `.ttf` remains the font authority.

After changing a host catalog or the repertoire, run `node scripts/update-body-font.mjs` from `firmware/` with `fontbm` available. `node scripts/update-body-font.mjs --check` verifies both checked-in outputs against the source inputs. The CJK UI font has its own generator and provenance in `StackchanCJK-Regular.README.md`.

The atlas is explicitly packed into one 1024×768 page. The previous default 1024×1024 allocation left avoidable space; repacking preserves all 7,170 glyphs, each raster, offsets and advance width while reducing the one-bit atlas by 32 KiB. The single-page limit makes repertoire growth fail explicitly instead of silently producing an unregistered second texture. Increase the packing dimensions and recheck the 4 MB release artifact if new glyphs no longer fit.
