# 設定済みサーボの診断と校正

`calibration`、`dynamixel`、`setup_rs30x` を統合しました。本体で選択済みの SCServo / DYNAMIXEL / RS30X と、そのドライバーが所有する UART を利用します。

## 準備と操作

実際の配線・サーボ種別・ID・通信速度に本体設定を合わせます。専用ボードで固定される設定は、そのボードの値を使います。PWM やサーボなしの構成では `UNSUPPORTED` です。CoreS3 を含む機種名だけで全プロトコルが使えるわけではありません。

まず「対象サーボ」で Pan / Tilt を選び、「角度・状態を読む」を実行します。「±10° 動作確認」と「トルクを解放」で通常動作を確認します。読み取り値の `angleDeg` / `offsetDeg` は度です。DYNAMIXEL の `current` / `velocity` は機種固有のレジスター値で、A / rpm ではありません。

保存操作はメニューから明示的に選んだときだけ実行します。

- SCServo：「現在位置を正面として保存」。トルク解放後の物理位置を基準にオフセットを保存します。raw position を使うため、同じ位置で繰り返しても補正を累積しません。
- DYNAMIXEL：「サーボの LED を切り替え」「通信速度を 1 Mbps に保存」。速度は設定済みの両軸へ書き込みます。以後の動作は止め、本体の `driver.baudrate` も1000000へ合わせて再起動します。途中失敗の場合も、片側だけ速度が変わった可能性があるため再設定が必要です。
- 全3種：「ID を Pan=1 / Tilt=2 に保存」。選択軸の ID を変更します。接続済みの別サーボと ID が重複しない状態で使い、本体設定も一致させてください。

## 改造と復帰

アプリは raw driver や UART を生成しません。保存中は通常 motion とドライバーの周期処理を止め、終了要求でも進行中のバス操作が終わるまで待ちます。診断項目の追加は `maintenance` の型付き操作から始めます。

通信不能なら先に種別・配線・ID・速度を確認します。別の MOD を起動しても保存したサーボ設定は元には戻りません。旧例の起動直後の設定書き込み・固定サーボ生成・連続自動運動は、設定済み機器への明示操作へ置き換えました。実機での校正・可動域の受入は未実施です。

## ビルドと導入

このブランチの app API 2 / host API 7 が必要です。古い host / XSA は更新・再ビルドします。`firmware/` で依存関係とツールチェーンを準備して実行してください。

```sh
npm run mod:build -- mods/examples/servo_diagnostics/manifest.json
npm run mod -- mods/examples/servo_diagnostics/manifest.json
```

前者はビルド、後者は既定の CoreS3 への書き込みです。別機種は対応する `mod:stackchan_rt` / `mod:takao_core2_sg90` を使います。機種の宣言と利用できる機能を確認してください。[全例と共通の復帰手順](../README_ja.md)、[公開 SDK](../../../sdk/README_ja.md) に共通契約をまとめています。
